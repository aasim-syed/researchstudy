What moves at each step

  1. 1Mesh file path and options reach the CLI (quadremesh in.obj -o out.obj -f 5000) or the Python call quadremesh("in.obj", 5000); strokes and density maps go in as options.
  2. 2Optional: the PyTorch network predicts a guide direction per vertex (on CUDA if present) and passes it in as guide_field.
  3. 3quadremesh() receives the triangle mesh and parameters; everything after this runs in C++.
  4. 4Clean, manifold, consistently oriented triangles (duplicates welded, holes filled, broken edges repaired).
  5. 5The crease set: every edge with a dihedral angle above 35°, noise rejected, chains shorter than 3 L dropped.
  6. 6Cross field locked to the creases, plus a scale target that makes quads smaller near creases at the same total count.
  7. 7Raw quads per connected part from QuadriFlow's integer grid; parts it cannot solve go to Instant Meshes.
  8. 8Quads with an edge path snapped onto every crease, then smoothed and projected back onto the original surface.
  9. 9Coverage operations (near-miss snapping, path-edge subdivision, loops) kept only within the triangle budget and a singularity budget set at 85 % of Instant Meshes.
  10. 10Guards checked: mean SJ ≥ 0.81 or re-solve with less adaptive size; output ≤ 1.10 × target faces or re-solve. Optional: four solves scored by the evaluator, best valid one kept.
  11. 11The quad mesh (.obj with UVs) and its JSON quality report.
  12. 12The runner sends each of the 15 benchmark models to every method at the same face count.
  13. 13Each method's quad mesh goes to the evaluator.
  14. 14One JSON report per model and method (quads, SJ, distance, coverage, singularities, runtime).
  15. 15Scripts turn the reports into the summary tables, the coverage study, the crease-limit analysis, the code map and the visual report.
  16. 16Write-up PDF, README and visual report, with every number generated from the reports.
